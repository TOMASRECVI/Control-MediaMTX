PROBLEMAS RESUELTOS
================================================================================

1. ERROR 400 AL ELIMINAR ÚLTIMO ARCHIVO
   - Síntoma: Elimina perfectamente todos los archivos, pero al último salta error
   - Causa: Cuando no hay archivos, MediaMTX no puede encontrar el segmento
   - Solución:
     a) Backend ahora acepta "éxito parcial" si se eliminó el archivo
     b) Frontend refresca automáticamente después de cada eliminación
     c) Se espera 300-500ms a que MediaMTX procese cambios

2. INSTALACIÓN MANUAL COMPLICADA
   - Síntoma: Hay que editar docker-compose.yml manualmente
   - Solución: Script install.sh autodetecta todo

3. FALTA DE INFORMACIÓN DE DEBUGGING
   - Síntoma: No está claro por qué fallan operaciones
   - Solución: Nuevo endpoint /api/debug y script debug_api.sh

4. DOCUMENTACIÓN INCOMPLETA
   - Síntoma: Falta guía en español
   - Solución: Archivos INSTRUCCIONES.md, README.md, CHANGELOG.md

================================================================================
CÓMO INSTALAR LOS CAMBIOS
================================================================================

OPCIÓN 1: Automática (Recomendado)
─────────────────────────────────────────────────────────────────────────────
cd /home/user/mediamtx-manager
bash install.sh

El script:
  1. Detectará tu contenedor MediaMTX
  2. Configurará red y volúmenes automáticamente
  3. Te pedirá seleccionar un puerto (default 8080)
  4. Construirá e iniciará el contenedor
  5. Verificará conectividad
  6. Te mostrará la URL para acceder

OPCIÓN 2: Manual
─────────────────────────────────────────────────────────────────────────────
cd /home/user/mediamtx-manager
docker compose down
docker compose up -d --build

Luego accede a: http://127.0.0.1:8080

VERIFICACIÓN
================================================================================

1. Verifica que todo está en su lugar:
   ls -la *.md *.sh *.py docker-compose.yml

2. Reconstruye el contenedor:
   docker compose down && docker compose up -d --build

3. Verifica logs:
   docker logs mediamtx-manager --tail=20

4. Accede a la interfaz:
   http://127.0.0.1:8080

5. Prueba la eliminación:
   - Selecciona un segmento
   - Elimina
   - Debería recargar automáticamente
   - Sin error disruptivo incluso si MediaMTX falla

SOPORTE Y TROUBLESHOOTING
================================================================================

Si algo no funciona:

1. Consulta INSTRUCCIONES.md
   • Sección "Problemas Comunes"

2. Ejecuta diagnóstico:
   docker exec mediamtx-manager bash /app/debug_api.sh

3. Revisa logs:
   docker logs mediamtx-manager --tail=100 --timestamps

4. Reinicia si es necesario:
   docker compose down
   docker compose up -d --build

5. Verifica endpoint específico:
   curl http://127.0.0.1:8080/api/health | jq .
